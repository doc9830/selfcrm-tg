# Telegram Mini App: архитектура и эксплуатация

Документ описывает, как SelfCRM работает внутри Telegram: из чего состоит слой Telegram, как
устроен запуск, тема, кнопка «Назад», офлайн-режим и резервные копии, что с безопасностью и как
диагностировать проблемы. Общая архитектура приложения — в [ARCHITECTURE.md](../ARCHITECTURE.md).

## 1. Из чего состоит решение

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ Telegram-клиент                                                             │
│  • inline-кнопка web_app в ответ на /start                                  │
│  • кнопка меню чата (web_app) — «Открыть SelfCRM»                           │
│  • BackButton, тема (light/dark), safe area, размеры окна                    │
└───────────────────────────────┬──────────────────────────────────────────────┘
                                │  открывает HTTPS-страницу Mini App
┌───────────────────────────────▼──────────────────────────────────────────────┐
│ GitHub Pages: https://doc9830.github.io/selfcrm-tg/                          │
│  статика из dist/ (index.html, JS/CSS, sw.js) — серверной логики нет         │
└───────────────────────────────┬──────────────────────────────────────────────┘
                                │  index.html → telegram-web-app.js → main.tsx
┌───────────────────────────────▼──────────────────────────────────────────────┐
│ SelfCRM (React SPA)                                                          │
│  Screens → DataContext → KVStore (localStorage) — копия уходит в облако      │
└──────────────────────────────────────────────────────────────────────────────┘

Отдельно, на машине разработчика:
  scripts/telegram-bot.mjs —— long polling @fastcrm_bot: /start, /help, /whatsnew,
                              кнопка «Открыть SelfCRM» и подсказка на присланный файл копии
```

Роли разделены жёстко:

- **Бот** — точка входа. Никакой CRM-логики и никаких данных: он отвечает на `/start`, `/help`
  и `/whatsnew` (changelog последнего релиза Android-версии — публичный GitHub API, без секретов),
  отдаёт кнопку, запускающую Mini App, и ставит кнопку меню — общую (для всех) и в чате при
  первом сообщении пользователя. Присланный файл копии он не скачивает: только подсказывает, как
  вернуть из него данные.
- **GitHub Pages** — доставка статики. Никаких секретов и никаких данных пользователя.
- **Mini App** — само приложение. Вся логика и все данные — здесь, в хранилище устройства; наружу
  уходит только резервная копия — по кнопке «Сохранить» в облако Telegram (раздел 8).

## 2. Файлы слоя Telegram

| Файл                               | Ответственность                                                                 |
| ---------------------------------- | ------------------------------------------------------------------------------- |
| `src/telegram/webapp.ts`           | Типы WebApp API и null-safe доступ: `getTelegramWebApp()`, `isTelegramEnvironment()`, `insideTelegramWebView()`, `openExternalLink()` / `openBotChat()`, `TELEGRAM_BOT_URL`, `getTelegramUserId()`, `getTelegramUserLabel()` |
| `src/telegram/environment.ts`      | `initTelegramEnvironment()` (`ready()`, `expand()`, слежение за `viewportChanged`, переменные `--tg-height` / `--tg-stable-height`), `syncTelegramChrome()`, `telegramColorScheme()`, `setTelegramBackButtonVisible()`, `onTelegramBackButton()`, `onTelegramThemeChange()` |

| `src/components/TelegramShell.tsx` | React-мост: вызывает функции выше и связывает события Telegram с роутером (`backTarget`) и темой (`applyTelegramScheme`). Ничего не рендерит |
| `index.html`                       | Подключение официального `telegram-web-app.js`, CSP, тема до первой отрисовки    |
| `src/index.css`                    | `--safe-top` / `--safe-bottom` (safe area Telegram → `env(safe-area-inset-*)`), высота окна |
| `public/sw.js`                     | Service worker: кэш оболочки страницы для офлайн-запуска                         |
| `scripts/telegram-bot.mjs`         | Бот-лаунчер: `--setup` (команды `/start`, `/help`, `/whatsnew`, общая кнопка меню, `--chat <id>` — для чата), `--whatsnew` — предпросмотр текста, long polling; при первом сообщении ставит кнопку меню в чате, на присланный документ отвечает подсказкой о восстановлении |
| `.github/workflows/deploy-pages.yml` | Сборка и публикация статики на GitHub Pages                                    |
| `.github/workflows/sync-from-selfcrm.yml` | Перенос новых функций Android-версии: `scripts/sync-from-selfcrm.mjs`, отчёт в PR ([UPSTREAM_SYNC.md](./UPSTREAM_SYNC.md)) |
| `.github/workflows/ci.yml`         | Типы, тесты и сборка на pull request (PR от синхронизации проверяется внутри своего workflow) |

Сторонние пакеты не нужны: официальный скрипт создаёт `window.Telegram.WebApp`, а типы написаны
вручную — только то, что реально применяется.

## 3. Запуск приложения по шагам

1. Пользователь нажимает «Открыть SelfCRM» в боте (или отправляет `/start`). Кнопка берётся из
   ответа бота на `/start` либо из кнопки меню: общую ставит `npm run bot:setup`, у конкретного
   человека — сам бот при первом сообщении (общая настройка в Telegram применяется не мгновенно).
2. Telegram открывает `https://doc9830.github.io/selfcrm-tg/` в своём WebView.
3. Инлайн-скрипт в `index.html` до первой отрисовки ставит `data-theme`: выбор пользователя в
   SelfCRM → тема Telegram (`WebApp.colorScheme`) → тема системы. Так нет «мигания» светлой темы.
4. Загружается `telegram-web-app.js` (кэшируется service worker), создаётся
   `window.Telegram.WebApp`.
5. React монтирует `TelegramShell`: `ready()`, `expand()`, подписка на `viewportChanged`,
   `themeChanged` и `BackButton`.
6. Вне Telegram шаги 3–5 деградируют безопасно: тема берётся из системы, а все вызовы WebApp API
   становятся пустыми (`null` / `() => {}`).

## 4. Тема оформления

Источник истины — тема SelfCRM (`selfcrm:theme` в `localStorage`, атрибут `data-theme` на `<html>`).

- **Telegram → SelfCRM.** При запуске и по событию `themeChanged` вызывается
  `applyTelegramScheme()`, но **только если пользователь не выбирал тему вручную**. Ручной выбор
  («Светлая» / «Тёмная») приоритетнее, пока его не сбросят на «Системную».
- **SelfCRM → Telegram.** При каждом изменении темы `syncTelegramChrome()` перекрашивает шапку и
  фон клиента: светлая тема — `#ffffff`, тёмная — `#0f172a` (те же цвета, что в `--surface` и
  `--bg`). Клиенты без `setHeaderColor` остаются со своим оформлением — ошибки проглатываются.

## 5. Кнопка «Назад»

Системная кнопка Telegram повторяет логику стрелочки в шапке SelfCRM (`src/utils/back.ts`):

1. сначала рассылается `BACK_EVENT` — открытые окна закрываются сами и «съедают» нажатие;
2. иначе берётся `backTarget(route)`: экран клиента → список клиентов, раздел → главная и т. д.;
3. если возвращаться некуда (главная), вызывается `Telegram.WebApp.close()` — Mini App
   закрывается, как и ожидает пользователь.

Видимость кнопки выставляется по тому же `backTarget(route)`: на верхнем уровне разделов она
скрыта, потому что выход оттуда делает сам Telegram. Логика не дублируется с `SystemBack`
(Android): оба компонента работают через общие события `BACK_EVENT` и `backTarget`.

## 6. Размеры окна и safe area

- `--safe-top` / `--safe-bottom` в `src/index.css` объявлены как
  `var(--tg-safe-area-inset-top, env(safe-area-inset-top))` и аналогично для низа: Telegram
  отдаёт свои вставки, обычный браузер — системные. Отступы шапки и нижней навигации берутся из
  этих переменных, поэтому вырез камеры и системные жесты ничего не перекрывают.
- Высота приложения — `--tg-stable-height` (из `viewportStableHeight`, обновляется по
  `viewportChanged`) с запасными вариантами `--tg-viewport-stable-height` и `100dvh`. Это
  исключает «прыжки» вёрстки при появлении экранной клавиатуры.

## 7. Офлайн-режим

`public/sw.js` кэширует оболочку приложения (HTML, ассеты с хешами в именах,
`telegram-web-app.js`) и отдаёт её при отсутствии сети: Mini App открывается и работает офлайн,
потому что все данные лежат на устройстве. Новая сборка приносит новые имена ассетов, поэтому
устаревший кэш не мешает обновлению. Сеть нужна только для подсказок адресов, маршрута и работы
с резервной копией: в облаке Telegram (сохранить и восстановить) или в чате с ботом (отправить
файл и скачать его на другом устройстве).

## 8. Резервные копии

Данные Mini App лежат в localStorage WebView устройства, поэтому копия — единственный способ
перенести базу на другое устройство и вернуть её после очистки данных Telegram. В мини-приложении
копия сохраняется в **облако Telegram** (`WebApp.CloudStorage`, Bot API 6.9+): облако привязано к
аккаунту Telegram, а не к телефону, поэтому копия доступна с любого устройства и восстанавливается
из настроек:

```text
SelfCRM → Настройки → Резервная копия → «Сохранить» (копия в облаке Telegram)
   ↓  SelfCRM_backup_2026-09-25_12-30.json — тот же конверт копии, порезанный на части
selfcrm-backup-part-0…N + selfcrm-backup-manifest в облаке аккаунта Telegram
   ↓  другое устройство → SelfCRM из того же бота → «Восстановить из облака»
показ состава копии → подтверждение → данные заменены
```

Запасной путь — файл и чат с ботом. Он работает в браузере, в Android-сборке и в старом клиенте
Telegram, где облака (Bot API младше 6.9) нет:

```text
SelfCRM → Настройки → Резервная копия → «Создать»
   ↓  SelfCRM_backup_2026-09-25_12-30.json (скачивание из WebView)
пользователь сам отправляет файл в чат с @fastcrm_bot
   ↓  файл остаётся в истории чата Telegram
другое устройство → SelfCRM → «Восстановить из файла» → файл из Telegram
```

В браузере и Android-сборке в разделе настроек есть строка «Копия файлом в чат с ботом» с кнопкой
«Сохранить и открыть чат»: она сохраняет файл копии и открывает чат с ботом, чтобы не искать
бота вручную. Файл прикрепляет **пользователь** (📎 → Файл): мини-приложение не может отправить
файл за него — в Bot API нет метода, который кладёт файл из устройства пользователя в чат.

Когда облака нет, раздел «Резервная копия» не просто прячет облачные кнопки, а объясняет причину:
«Облако Telegram: только внутри Telegram» (браузер и Android-сборка — надо открыть SelfCRM из бота)
или «Облако Telegram: нужно обновить Telegram» (клиент младше Bot API 6.9). Признак —
`cloudStorageAvailability()` в `src/telegram/cloudStorage.ts`: он отдельно проверяет, что
`window.Telegram.WebApp` — это действительно клиент Telegram, потому что официальный
`telegram-web-app.js` создаёт похожий объект-заглушку и в обычном браузере (`initData` пуст,
`platform = 'unknown'`).

Тем же данным верит `isTelegramEnvironment()` (`src/telegram/webapp.ts`): окружение считается
телеграмным по `initData` от клиента или по названной им платформе, а пустой `initData` вместе с
`platform = 'unknown'` — это обычный браузер. Раньше признаком был сам объект `window.Telegram.WebApp`,
и в браузере приложение считало себя мини-приложением: ссылки «открывались в пустоту», а PDF не
сохранялся. Отдельно есть `insideTelegramWebView()` — «мы внутри WebView клиента»: он охватывает и
мини-приложение (по данным клиента), и встроенный браузер Telegram (данных мини-приложения там нет,
но события доходят через `window.TelegramWebviewProxy` или `window.external.notify`). От этого
признака зависит и открытие ссылок (`openExternalLink()`), и сохранение файлов.

Роли в этой схеме:

- **Mini App** собирает копию и читает её при восстановлении. Доступа к истории сообщений у него
  нет и не появится: автоматический поиск последней копии в переписке невозможен без серверной части,
  которой у SelfCRM нет.
- **Облако Telegram** (`CloudStorage`) хранит копию в аккаунте пользователя: серверной части у SelfCRM
  нет, значения пишет и читает клиент по запросу мини-аппа, а ключи видит только этот же аккаунт.
- **Telegram (чат с ботом)** хранит файл копии как обычное сообщение чата — это запасной способ.
  Пользователь может удалить его, скачать на другом устройстве или отправить себе в «Избранное» —
  приложение это не контролирует.
- **Бот** отвечает на присланный документ подсказкой, как вернуть данные (`backupMessage`), и **не**
  скачивает файл: `getFile` не вызывается, данные CRM в боте не хранятся.

Как это устроено внутри:

- Облачная копия — `src/db/cloudBackup.ts` поверх промисной обёртки `src/telegram/cloudStorage.ts`
  (`WebApp.CloudStorage`, Bot API 6.9+). Значение в облаке ограничено 4096 символами, поэтому конверт
  копии режется на части по 3500 **байт** (в копии кириллица — до двух байт на символ). Части лежат под
  ключами `selfcrm-backup-part-0…N`, а `selfcrm-backup-manifest` хранит дату, имя файла, число частей и
  состав копии — по нему настройки показывают «Сохранена 25.09.2026, 12:30 · Клиентов: 12». Запись идёт
  частями, манифест — последним: прерванная запись не портит прежнюю копию. Ключей в облаке не больше
  1024 (манифест занимает один), то есть копия до ~3,5 МБ; больше — предложение сохранить копию файлом.
  Ключи состоят только из разрешённых клиентом символов (латиница, цифры, «_», «-», до 128 символов):
  двоеточия и кириллица недопустимы — клиент отвечает на них `STORAGE_KEY_INVALID`. Проверка
  `isValidCloudKey()` в `src/telegram/cloudStorage.ts` не пускает такой ключ к клиенту и объясняет
  причину понятным текстом, а не кодом ошибки.
- Экспорт файла — обычное скачивание в браузере и в Android-сборке (`downloadJson`): в мини-приложении
  Telegram этот путь не работает (клиент игнорирует `<a download>` и blob-ссылки, а `downloadFile`
  принимает только адреса `https:`), поэтому основная кнопка там — облако. `shareMessage` тоже не
  используется — ему нужно «подготовленное» сообщение от бота (серверная часть).
- Чек в PDF в мини-приложении тоже уходит не файлом, а **ссылкой** (`src/pdf/receiptDelivery.ts`):
  данные чека упаковываются в адрес страницы (`#/receipt?d=…` — JSON, сжатый `deflate-raw`, в
  base64url), и клиент открывает выбор чата по `https://t.me/share/url?url=…&text=…`. Получатель
  открывает ссылку в браузере Telegram, видит тот же чек и сохраняет его как PDF («Сохранить PDF»
  или «Печать» → «Сохранить в файлы»). Сервер для этого не нужен: чек целиком лежит в адресе, он
  же и есть передача данных — так путь работает и на iPhone, где файл из мини-приложения отдать
  нечем. Ссылка выбирается раньше Web Share API намеренно: в WebView на Android `navigator.share`
  и `navigator.canShare` объявлены и на пробный PDF отвечают «да», но системного меню у WebView
  нет — промис не завершается, и нажатие «Чек (PDF)» выглядело как «ничего не произошло» (на iOS
  тот же путь работал, потому что файлы в Web Share API там не поддержаны). Если выбор чата не
  открылся, ссылка ложится в буфер обмена, а под кнопкой «Чек (PDF)» остаются кнопки «Скачать PDF» и
  «Скопировать ссылку». Файл из мини-приложения всё-таки достаётся — через браузер: «Скачать PDF» в
  карточке заказа и «Скачать PDF в браузере» на странице чека открывают ту же страницу с признаком
  `dl=1` (`receiptDownloadUrl()`), и в браузере PDF скачивается сразу, без второго нажатия
  (`receiptWantsDownload()` → `autoDownload` в `src/screens/ReceiptView.tsx`). В Android-сборке
  SelfCRM (Capacitor) путь другой: PDF пишется в `Directory.Cache` и открывается системным меню
  «Поделиться», а `saveReceiptPdf()` внутри Telegram (мини-приложение или его встроенный браузер)
  честно отвечает «файл отдать нечем».
- Формат файла — конверт `{format, version, createdAt, appVersion, app, data}`
  (`src/db/backupFormat.ts`) с дублями ключей снимка в корне: так файл читает и Android-сборка SelfCRM.
  Импорт принимает оба варианта, а копию с более новой версией формата отклоняет с понятным сообщением.
- Восстановление — только после подтверждения: приложение показывает, что в копии (клиенты, товары,
  заказы, напоминания), и предупреждает, что текущие данные будут заменены. Кнопка «Создать backup и
  продолжить» сначала сохраняет копию текущего состояния (в Telegram — в облако, вне его — файлом),
  и лишь затем заменяет данные.
- Ссылка на бота в интерфейсе — обычная `https://t.me/fastcrm_bot`. Открывает её клиент Telegram
  методом `WebApp.openTelegramLink` (при отсутствии — `openLink`), в браузере — новой вкладкой, в
  Android-сборке — через `window.open(url, '_system')`. Обычный `window.open(url, '_blank')` в
  WebView мини-приложения игнорируется: без этих ветвей нажатие заканчивалось только вибрацией, а
  чат не открывался. Если открыть ссылку не удалось (`openBotChat()` вернул `'failed'`), интерфейс
  показывает адрес бота текстом, чтобы пользователь нашёл чат сам.
- Токен бота в приложение и в bundle не попадает: он нужен только локальному скрипту бота.
